# WebdriverIO UI Automation

Учебный проект по автоматизации UI-тестирования веб-приложений с использованием **JavaScript, WebdriverIO и Mocha**.

Проект создан для практики написания автотестов, работы с браузером, проверки пользовательских сценариев и освоения подходов к организации тестового кода.

Тестирование проводится на публичных веб-приложениях: GitHub, документации WebdriverIO и демонстрационной странице авторизации.

## Технологический стек

| Технология | Назначение |
|---|---|
| JavaScript | Язык написания автотестов |
| WebdriverIO | Автоматизация взаимодействия с браузером |
| Mocha | Организация и выполнение тестов |
| Node.js | Среда выполнения JavaScript |
| Chrome | Браузер для запуска тестов |

Для проверок используется встроенный в WebdriverIO механизм `expect`.

## Организация автотестов

В проекте используются два подхода к организации тестов.

### Классический Mocha

В учебных тестах действия и проверки выполняются внутри `it()`.

```javascript
it('Открыть главную страницу', async () => {
    await browser.url('https://webdriver.io/');

    await expect(browser).toHaveUrl('https://webdriver.io/');
});
```

### Разделение действий и проверок

В GitHub-тестах используется дополнительная функция `check()`, которая позволяет визуально отделять действия от проверок.

```javascript
const { check } = require('../helpers/check');

describe('TC-001: Главная страница GitHub', () => {
    const DATA = {
        url: 'https://github.com/',
        title: 'GitHub',
    };

    it('Открыть главную страницу', async () => {
        await browser.url(DATA.url);
    });

    check('Проверить URL страницы', async () => {
        await expect(browser).toHaveUrl(DATA.url);
    });

    check('Проверить заголовок страницы', async () => {
        await expect(browser).toHaveTitle(
            expect.stringContaining(DATA.title)
        );
    });
});
```

**Принципы организации GitHub-тестов:**

- `describe()` — группировка шагов одного сценария.
- `DATA` — хранение URL, селекторов и тестовых данных.
- `it()` — действия с браузером и интерфейсом.
- `check()` — проверки ожидаемого результата.
- `expect()` — сравнение фактического и ожидаемого поведения.

Функция `check()` реализована как обёртка над Mocha `it()`. Поэтому каждый шаг регистрируется как отдельный тест Mocha. Такие шаги могут зависеть от состояния браузера, созданного предыдущими шагами, и пока не являются полностью независимыми тестами.

## Установка и запуск

### Требования

Для локального запуска необходимы:

- Node.js и npm
- Google Chrome

### 1. Клонирование репозитория

```bash
git clone https://github.com/osiern/wdio-project.git
cd wdio-project
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Запуск тестов

**Все тесты:**

```bash
npx wdio run wdio.conf.js
```

**Отдельный тестовый файл:**

```bash
npx wdio run wdio.conf.js --spec ./test/specs/github-1.js
```

**Все GitHub-тесты:**

```bash
npx wdio run wdio.conf.js --spec "./test/specs/github-*.js"
```

**Отдельный E2E-тест авторизации:**

```bash
npx wdio run wdio.conf.js --spec ./test/specs/test.e2e.js
```

Команды выполняются из корневой директории проекта.

## Конфигурация и результаты

Основные настройки находятся в `wdio.conf.js`.

| Параметр | Значение |
|---|---|
| Test runner | Local |
| Framework | Mocha |
| Browser | Chrome |
| Reporter | Spec |
| Default wait timeout | 10 секунд |
| Mocha timeout | 60 секунд |
| Max instances | 10 |

WebdriverIO запускает тестовые файлы, соответствующие шаблону `./test/specs/**/*.js`.

Результаты выполнения отображаются в терминале с помощью **Spec Reporter**: названия тестов, статусы прохождения и информация об ошибках.

В учебных сценариях также используются скриншоты элементов для практики работы с браузером.
